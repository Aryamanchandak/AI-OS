Photos, PDFs, Word docs and stray .md files all get an earlier entry gate before the point where the existing, unchanged Obsidian pipeline already begins. The pipeline itself never learns about photos or PDFs — it only ever sees a finished markdown note sitting in the vault.

What's still open, blocking a full end-to-end build

  1. Gate-by-extraction-method recommendation — DOCX / native-text PDF / plain .md skip the cockpit; scanned PDF and photos require it. Recommended in Component 1, awaiting your sign-off.
  2. Pending-approval staging — where a needs_approval=True extraction result lives between run_funnel producing it and the cockpit approving it later, in a different process. Not designed.
  3. Vault folder placement — where these notes land in the vault, naming, collision handling. Not designed.
  4. Metadata-block parsing — once the human-readable metadata block's shape is picked, something on the ingestion side has to read it back out during parse_source(). Not designed.
  5. Cockpit layout for scanned PDFs — if scanned PDFs share the photo gate, does the review UI need its own shape, or is "page image next to text" enough? Not decided.
  6. Two smaller open notes carried from the full plan: the cut-off quality-check sentence (§8 Q4) and whether to open real ticket numbers now for underline support / local-cost spellcheck / hand-edit highlight box (§8 Q5).
