# Causal Scenario Engine — Build Spec

## What you are building

A standalone tool. An analyst types a situation in plain English ("RBI cuts repo by 50bp"). The system returns:

1. A causal graph of what that situation moves, and in which direction.
2. Four scenarios, generated by toggling two named unknowns.
3. A per-outcome trace so the analyst can see *why* each result happened.

**This is being built in isolation.** Do not assume any existing infrastructure, database, auth, config system, or codebase. There is none. Everything runs in-memory, per session.

---

## Non-negotiable design rules

Read these before writing any code. Violating them means a rebuild.

**Rule 1 — Extraction is ONE call for the whole graph.**
Do not build recursive per-node extraction ("what does this node cause?" repeated). That produces 85+ LLM calls at depth 3, takes minutes, and generates duplicate nodes ("consumer demand" / "household spending" / "discretionary consumption" as three separate nodes). One call sees the whole picture and deduplicates naturally.

**Rule 2 — Propagation contains ZERO LLM calls.**
`propagate.py` must be a pure function. If you find yourself importing the LLM client into that file, stop — that is a bug. Sign propagation is multiplication. Magnitude decay is a lookup. Both are deterministic and instant. This is what makes the tool auditable and what makes scenario re-runs free.

**Rule 3 — No agent loop, no ReAct, no LangChain/LlamaIndex/CrewAI.**
The pipeline is fixed and known in advance: extract → propagate → synthesize. There is no point at which the system needs to decide what to do next. Use the LLM SDK directly.

**Rule 4 — Confidence is three buckets, never a float.**
`low` / `med` / `high`. A model reporting `0.73` confidence is fake precision.

**Rule 5 — Build and test files 1–3 before touching the UI.**
If propagation is correct, the demo is 80% done. If you build the UI first you will debug prompts and layout simultaneously.

## Build order

Do these strictly in order. Test each before moving on.

---

### Step 1 — `schema.py`

Dataclasses only. No logic.

```python
Sign      = int          # -1, 0, +1
Magnitude = str          # "low" | "med" | "high"
NodeType  = str          # "intervention" | "intermediate" | "outcome"

@dataclass
class Node:
    id: str              # "n1", "n2", ...
    label: str           # "INR spot", "corporate borrowing cost"
    node_type: NodeType
    sign: Sign = 0       # filled in by propagation
    magnitude: Magnitude = "med"
    contested: bool = False
    trace: list[str] = field(default_factory=list)

@dataclass
class Edge:
    src: str
    dst: str
    sign: Sign           # +1 = src up pushes dst up; -1 = inverse
    strength: Magnitude
    mechanism: str       # ONE sentence, why src moves dst

@dataclass
class Unknown:
    id: str              # "u1", "u2"
    question: str        # "Does the RBI cut again in the next quarter?"
    affects_node_id: str # which node this unknown sets the sign of

@dataclass
class Graph:
    nodes: list[Node]
    edges: list[Edge]
    unknowns: list[Unknown]   # exactly 2
```

Also define the JSON schema dict used to force the extraction tool-call output. It must mirror the above exactly.

**Test:** instantiate a 5-node graph by hand in a scratch script. That hand-built graph becomes your propagation test fixture.

---

### Step 2 — `extract.py`

One function:

```python
def extract_graph(situation: str) -> Graph
```

One LLM call, using **tool-calling with a forced schema** (`tool_choice` set to the extraction tool). Do not parse free-text JSON out of a prose response.

**Hard constraints to put in the prompt:**

- Return **8–15 nodes**. Not more. 15 nodes is the readable limit on one screen.
- Max causal depth 3 hops from the intervention node.
- Exactly **one** node with `node_type: "intervention"` — this is the situation itself, and it is the graph root.
- **3–5** nodes must be `node_type: "outcome"` — these are the things an analyst actually cares about and they must be graph leaves (no outgoing edges).
- Everything else is `intermediate`.
- Every edge needs a one-sentence `mechanism`. Reject/retry if any are empty.
- Return exactly **2 unknowns** — genuine binary uncertainties that a domain expert would argue about, each tied to a specific `affects_node_id`. Not "will the effect be large" (that's magnitude, not an unknown). Good: "Does oil hold above $90?" "Do foreign investors treat this as risk-on?"

**Post-call validation (fail loudly, retry once):**

- graph is acyclic (`networkx.is_directed_acyclic_graph`)
- all edge `src`/`dst` ids exist in nodes
- exactly one intervention node
- every outcome node has zero outgoing edges
- exactly 2 unknowns, each pointing at a real node id

**Test:** run on a hardcoded situation string, pretty-print the resulting graph, eyeball it. Do this before writing anything else.

---

### Step 3 — `propagate.py`

The heart of the system. **Pure function. No LLM. No I/O.**

```python
def propagate(graph: Graph, assignment: dict[str, Sign]) -> Graph
```

`assignment` maps unknown id → +1 or -1, e.g. `{"u1": +1, "u2": -1}`.

**Algorithm:**

1. Deep-copy the graph so the original is untouched.
2. Build a `networkx.DiGraph` from the edges; take `topological_sort`.
3. Set the intervention node to `sign = +1`, `magnitude = "high"`.
4. Apply the assignment: for each unknown, set its `affects_node_id` node's sign to the assigned value and mark that node as assignment-seeded (its sign is not overwritten by parents).
5. Walk nodes in topological order. For each node with incoming edges:
   - For each incoming edge: `contribution = parent.sign * edge.sign`
   - Sum contributions.
     - sum > 0 → `sign = +1`
     - sum < 0 → `sign = -1`
     - sum == 0 with at least one non-zero contribution → `sign = 0`, `contested = True`
   - If contributions have mixed signs (some +, some −), set `contested = True` regardless of the sum.
   - Magnitude: take the strongest incoming edge strength, then decay one bucket per hop from the intervention node (`high → med → low`, floor at `low`). Hop distance = shortest path length from the intervention node.
   - Append to `node.trace`: one string per incoming edge, e.g. `"n1(+) --[+1: repo cut lowers funding costs]--> n4(+)"`.
6. Return the resolved graph.

**Test — write `test_propagate.py` before wiring the UI.** Use the hand-built fixture from step 1:

- single chain, all `+1` edges → everything positive
- one `-1` edge mid-chain → sign flips from that point down
- two parents with opposite contributions → node marked `contested`
- magnitude decays correctly across 3 hops
- runs in well under a millisecond

If these pass, the hard part is done.

---

### Step 4 — `synth.py`

```python
def synthesize(resolved: Graph, scenario_name: str) -> str
```

One LLM call per scenario. Pass in only the **outcome nodes** with their signs, magnitudes, contested flags, and traces — not the full graph.

Ask for **3 sentences**: what happens, the mechanism that drove the biggest move, and what would falsify it. Plain prose, no headers, no bullets.

Call it for all four scenarios in parallel via `ThreadPoolExecutor`.

**Total LLM calls per run: 1 extraction + 4 synthesis = 5. Target wall-clock ~20 seconds.**

---

### Step 5 — `main.py` (Streamlit)

```
Text input:  "Describe the situation"
Button:      "Run"

-> spinner: "Building causal graph..."   (extract)
-> spinner: "Propagating..."             (4x propagate, instant)
-> spinner: "Writing scenarios..."       (4x synth, parallel)
```

**Scenario generation:** the two unknowns give four assignments — `(+,+) (+,-) (-,+) (-,-)`. Name each scenario from the unknown questions, e.g. *"RBI cuts again / oil holds"*.

**Output layout:**

1. **Scenario table** — 4 rows (scenarios) × N columns (outcome nodes). Each cell shows an arrow and magnitude: `↑↑` high-up, `↑` med-up, `·` low/flat, `↓` med-down, `↓↓` high-down, `⚠` contested. This table is the product — make it the first thing on screen.
2. **Narrative** — the 3-sentence synthesis under each scenario name.
3. **Expander: "Show the graph"** — full node list and edge list with mechanisms.
4. **Expander per outcome: "Why?"** — the node's `trace` lines, top to bottom.

Keep styling minimal. Default Streamlit is fine. No custom CSS.

---

## Stretch (only after everything above works)

**Edge perturbation.** Flip one edge's sign, re-run propagation, see which outcomes changed. Since propagation is pure arithmetic this is milliseconds. Loop over all edges, report which outcomes are robust (unchanged under most flips) and which hang on a single contested link.

This is roughly 20 lines of code and it is the most convincing thing in the demo — it shows structural sensitivity, which no prose-generating LLM can fake. But it only exists because propagation is deterministic. Do not build it before steps 1–5 are solid.

---

## Definition of done

- `streamlit run main.py`, type a situation, get four scenarios in under 30 seconds
- every outcome can be traced back through named mechanisms to the intervention
- `test_propagate.py` passes
- zero LLM calls inside `propagate.py`
