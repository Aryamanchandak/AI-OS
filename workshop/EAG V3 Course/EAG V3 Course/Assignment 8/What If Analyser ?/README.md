# Causal Scenario Engine

Type a situation in plain English (e.g. *"RBI cuts the repo rate by 50bp"*) and get:

1. **Grounded research** — ranked public sources, exact passages, and claims
   classified as fact, forecast, inference, or assumption.
2. **A challenged causal graph** — one selected critic and one adjudication
   round before the graph is shown.
3. **Four scenarios** — generated by toggling two named unknowns
   `(+,+) (+,-) (-,+) (-,-)`.
4. **An auditable trace** — sources, edge evidence status, graph diff, and exact
   load-bearing links.
5. **Visible model spend** — live Gemini call/token counts and an estimated INR
   cost retained with every completed result.

Everything runs in memory. A completed result stays visible while a new job is
running and is replaced only after that job succeeds. No database or auth is
required.

## How it works

The pipeline is fixed:

**plan → retrieve/rank → claims (parallel batches) → build → one critic → one
adjudicator → verify load-bearing edges → propagate → synthesize (parallel)**.

There is no agent loop and adjudication is capped at exactly one round. See
[`docs/WORKFLOW.md`](docs/WORKFLOW.md) for the full stage-by-stage contract
and a file-by-file guide to what every piece of code does.

| File | Role | LLM calls |
|------|------|-----------|
| `engine/schema.py` | shared dataclasses + Pydantic structured-output contracts | — |
| `engine/research.py` | plan, retrieve, clean, deduplicate, rank, and extract claims | 3 Quick / 5 Deep |
| `engine/extract.py` | brief + claims → evidence-aware `Graph`, with bounded repair | 1 normally |
| `engine/metering.py` | thread-safe Gemini token/call accounting and INR estimate | — |
| `engine/debate.py` | one critic, one adjudicator, graph diff, edge verification | 3 |
| `engine/sensitivity.py` | exact load-bearing edge selection | 0 |
| `engine/propagate.py` | **pure arithmetic** — resolves each node's sign/magnitude/contested/trace | 0 |
| `engine/synth.py` | resolved outcomes → 3-sentence note, four scenarios in parallel | 4 |
| `engine/pipeline.py` | framework-neutral orchestration + recoverable failure behavior | — |
| `engine/presentation.py` | pure labels, table cells, sensitivity rows, and DOT output | — |
| `web/app.py` | FastAPI jobs, SSE progress, and Jinja result rendering | — |
| `web/templates/` / `web/static/` | responsive HTML UI and local Graphviz renderer | — |
| `legacy/main.py` | legacy Streamlit rendering shell using the shared pipeline | — |
| `tests/test_propagate.py` / `tests/test_slim_pipeline.py` | offline deterministic and contract tests | — |

The project is laid out as:

```text
engine/   pure pipeline logic (research → graph → debate → propagate → synth)
web/      FastAPI app, HTML templates, static assets (current UI)
legacy/   older Streamlit shell, kept for comparison
tests/    offline deterministic + contract tests
docs/     planning notes and design history
```

**Quick total: 11 nominal LLM calls. Deep: 13 with one critic** (the slim
implementation intentionally does not stack a second Deep-mode critic). Invalid
graph output can add repair calls; the rejected graph and exact validation
errors are included in each repair request.

## Per-run cost reporting

Every Gemini request uses one shared metered client. The app reads the API's
returned input, output, cached-input, and thinking-token metadata, then streams
the accumulating call count, token count, and INR estimate to the sidebar. A
completed result permanently shows the same usage ledger. Failed runs keep the
last live estimate visible, so spent calls do not disappear with the result.

The default estimate uses Gemini 3.1 Pro Preview's standard paid-tier rates for
prompts up to 200k tokens, configured in `engine/metering.py`: `$2.00` per
million uncached text-input tokens, `$0.20` per million cached-input tokens, and
`$12.00` per million output tokens including thinking. USD is converted at
`₹95.00`. This is an estimate rather than an invoice: credits, taxes, prompts
over 200k tokens, and provider adjustments are not included.

Pricing and conversion can be updated without code changes:

```bash
export WHATIF_USD_TO_INR=95.00
export WHATIF_INPUT_USD_PER_M=2.00
export WHATIF_CACHED_INPUT_USD_PER_M=0.20
export WHATIF_OUTPUT_USD_PER_M=12.00
```

There is no rupee spending ceiling. `WHATIF_MAX_MODEL_CALLS` defaults to 30 as
a technical runaway guard, and `WHATIF_EXTRACTION_ATTEMPTS` defaults to 3.
Three causal hops remains a model readability target, but deeper acyclic graphs
are accepted because propagation, auditing, and rendering support them safely.

Propagation is deterministic: direction uses integer weights for the three
strength buckets (`low=1`, `med=2`, `high=3`), while magnitude uses the
strongest incoming edge and hop decay. Scenario reruns and edge perturbations
make no model calls.

Retrieval uses DuckDuckGo's public HTML search endpoint and direct page fetches.
If retrieval fails, the app visibly downgrades to brief-only graph construction
and keeps the rest of the deterministic analysis available.

## Setup

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export GEMINI_API_KEY=...                 # required for extract + synth
```

## Run

```bash
./what-if
```

This creates `.venv` and installs dependencies on first run if they don't
already exist, loads `GEMINI_API_KEY` from `.env`, and starts the server on
port `8731` (chosen to avoid clashing with common dev-server ports like 8000,
8080, 3000, or 5000). Override with `WHATIF_PORT=<port> ./what-if`.
Equivalent to running
`.venv/bin/python -m uvicorn web.app:app --reload --port 8731` directly.

Open <http://127.0.0.1:8731>, type a situation, and press **Build scenario
map**. Progress streams into the control panel while the analysis runs.

The older Streamlit shell remains available for comparison:

```bash
.venv/bin/python -m streamlit run legacy/main.py
```

## Reading the scenario table

`↑↑` high up · `↑` up · `▴` slight up · `·` flat · `▾` slight down · `↓` down · `↓↓` high down · `⚠` contested

> One deliberate deviation from the original spec: `low`-magnitude cells render as
> faint arrows (`▴`/`▾`) rather than `·`. Outcomes sit 2–3 hops deep, so magnitude
> almost always decays to `low` by the time it reaches them; collapsing that to `·`
> would hide the *direction* of every real outcome. `·` is reserved for a genuinely
> neutral sign. See `engine/presentation.py`.

## Structural sensitivity

The "Structural sensitivity" expander names the exact edges whose sign flip
changes an outcome. The six most consequential links across all four scenarios
are sent to one batched evidence-verification call; every other edge remains
explicitly `unverified`.

## Browser graph rendering

`web/static/viz-standalone.js` vendors Viz.js 3.9.0, which renders the DOT model in
the browser. The app therefore needs neither a `dot` executable nor a runtime
CDN request. Third-party attribution is in `docs/THIRD_PARTY_NOTICES.md`.
