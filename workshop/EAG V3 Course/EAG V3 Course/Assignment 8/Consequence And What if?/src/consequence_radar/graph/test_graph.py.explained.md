# `graph/test_graph.py`

Unit tests for `validate_graph` and `apply_patch` in `graph/__init__.py`. Uses the `graph` and `settings` fixtures defined in the project-root `conftest.py`: `graph` is a small 3-node/2-edge fixture (`N0` news_seed "Policy announced" → `N1` intermediate "Imported input cost" → `N2` sector_metric "Indian sector EBITDA", with one assumption `A1` and one directional estimate `Q1`) that is valid and reaches an Indian outcome; `settings` builds a real `Settings` object pointed at a temp sqlite file.

Four tests, each checking one invariant:

- **`test_graph_integrity_and_indian_path`**: the fixture graph passes `validate_graph(..., require_indian_path=True)` with zero problems (sanity check that the fixture itself is well-formed and reaches India). Then it breaks the first edge's `dst` to `"missing"` and asserts the "missing endpoint" problem string appears — covers the edge-endpoint referential check.
- **`test_dag_enforcement_and_patch_rollback`**: builds a `GraphPatch` that adds an edge `E3: N2 -> N0`, which together with the existing `N0->N1->N2` chain creates a cycle. Asserts `apply_patch` raises `GraphValidationError`. Crucially it then asserts the **original** `graph` object is untouched (`graph.version == 1` and `len(graph.edges) == 2`) — this verifies `apply_patch`'s `copy.deepcopy(graph)` at the top actually protects the caller's graph from partial mutation when validation fails downstream; a shallow-copy bug here would let the rejected edge leak into the caller's list.
- **`test_direct_seed_to_stock_price_is_invalid`**: retypes node `N2` as `market_outcome` with label `"Stock price"` and reroutes edge `E2`'s `src` to `N0` (the seed), producing a direct news_seed → "stock price" edge. Asserts the "direct news_seed" problem string fires — covers the hardcoded substring-matched structural rule in `validate_graph`.
- **`test_reference_integrity`**: sets edge `E1`'s `assumption_ids` to `["missing"]` and asserts the "missing assumption" problem fires — covers the assumption-id referential check.

These tests do not exercise the `add_assumption`/`update_assumption`/`add_estimate`/`update_estimate` branches of `apply_patch`, so the broken relative import bug documented in `graph/__init__.py.explained.md` (`from .models import Assumption` resolving to a nonexistent `consequence_radar.graph.models` module) is not caught by this test file.
