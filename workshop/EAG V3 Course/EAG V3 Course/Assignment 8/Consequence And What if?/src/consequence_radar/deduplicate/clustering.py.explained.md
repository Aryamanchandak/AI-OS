# `deduplicate/__init__.py`

Clusters `DiscoveryExtract` items that report the same underlying development into `DedupGroup` records, and assigns each cluster a conservative `FactualStatus`. Sits between `ingest` (produces extracts) and `select` (presumably ranks candidates from the deduplicated groups).

**Matching method: this is a plain bag-of-words Jaccard similarity over stemless lowercase tokens, not fuzzy string matching and not embeddings.** `_tokens(text)` regex-extracts `[a-z0-9]+` runs from `casefold()`-ed text, keeps only tokens longer than 2 characters, and drops a small hardcoded English stopword list (`the, a, an, and, or, to, of, in, on, for, with, from, says, said`). For each incoming extract it builds a token set from `headline + text[:800]` (only the first 800 characters of body text count toward matching, not the full 8000-character extract) and compares it against the *first member only* of each existing cluster (`cluster[0]`, not a running centroid or all members) using `|intersection| / |union|`. The first cluster scoring `>= threshold` (default `0.62`) wins; if none clears the bar, the extract starts a new singleton cluster. This is a single-pass, no-backtracking greedy clustering — cluster order is input order, and an extract is compared only against each cluster's original founding member, so a cluster's later members can never react to a new extract even if they'd have matched it better than the founder does.

**`infer_factual_status(text)`** is a hardcoded keyword-rule cascade (rumour < proposal < measured_outcome < implemented < enacted < formal_decision < announcement < analysis_or_forecast, checked in that literal order and returning on first match), falling back to `FactualStatus.UNCLEAR` if nothing matches. Note the rule order is not the same as the "caution" ordering used later — e.g. `"forecast"` markers are checked last among the specific rules, so a text containing both "approved" and "forecast" resolves to `FORMAL_DECISION`, not `ANALYSIS_OR_FORECAST`, purely because of list order.

**`deduplicate(extracts, threshold=0.62) -> list[DedupGroup]`** runs the clustering above, then for each cluster:
- Computes `infer_factual_status` per member and picks the **least-settled** status across the cluster via a separate, explicit `caution` ranking list (`RUMOUR, PROPOSAL, ANALYSIS_OR_FORECAST, UNCLEAR, ANNOUNCEMENT, FORMAL_DECISION, ENACTED, IMPLEMENTED, MEASURED_OUTCOME`) — the comment explains this is deliberate: one confident article can't promote a cluster containing a rumour-sourced article into settled fact.
- Picks an `authoritative_item_id` by max of `(bool(text), bool(published_at), len(text))` — i.e. prefer having text, then prefer having a timestamp, then prefer the longest text; ties beyond that fall to whichever member `max()` encounters first (stable but arbitrary for exact ties).
- `publisher_diversity` is the sorted set of distinct non-empty publishers in the cluster.
- `agreement`/`disagreement` are single fixed English sentences, not per-cluster generated text: `agreement` is populated only if the cluster has more than one member; `disagreement` is populated only if the members disagree on inferred factual status, and lists the comma-joined distinct status values.

Output shape: `DedupGroup(id="D{n}", member_item_ids=[...], authoritative_item_id=..., publisher_diversity=[...], agreement=[...], disagreement=[...], factual_status=...)`, IDs numbered `D1, D2, ...` in cluster-creation order.

Non-obvious/fragile points: threshold of 0.62 and the 800-char truncation window are hardcoded with no override plumbed through besides the function's own default parameter; single-word headlines or very short texts can produce tiny token sets where Jaccard similarity swings sharply on one shared/differing word; the O(n * clusters) comparison against only the founding member means cluster quality depends on input ordering.
