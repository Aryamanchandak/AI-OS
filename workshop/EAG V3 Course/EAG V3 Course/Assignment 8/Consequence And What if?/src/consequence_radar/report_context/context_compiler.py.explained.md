# `report_context/__init__.py`

Assembles the final `ReportContext` bundle — everything the report writer is allowed to see — from the graph, case selection, evidence, and audit trail produced by earlier pipeline stages, and enforces a token budget on the result by progressively trimming non-essential evidence. This is the last stage before `report.write_report`; it is the single place that decides what does and doesn't reach the LLM prompt.

**`compile_context(*, seed, graph, cases, claims, sources, findings, decisions, gaps, failures, token_budget) -> ReportContext`** builds the context in a fixed order:
1. `topological_graph(graph)` (from `..graph`, not deep-dived here) — presumably orders/validates the causal graph before inclusion.
2. `active_edge_claims`: claim IDs referenced (as supporting or contradicting) by any edge whose `status != "rejected"`.
3. `case_claims`: claim IDs referenced by the central case plus every material alternative case (`supporting_claim_ids` + `contradicting_claim_ids`).
4. `load_bearing = active_edge_claims | case_claims` — the set of claims that some part of the surviving graph/case structure actually depends on. This set is computed up front but only *used* if the budget is exceeded (step 6).
5. Splits the input `claims` list into `accepted` (verified, non-contradicting) and `contradicting` (verified, `stance == "contradicts"`) — **unverified claims (`passage_verified=False`) are silently dropped entirely**, never appearing in the context and never explained in `known_gaps`/`research_failures` unless the caller separately added them there.
6. Both claim lists and all sources are passed through excerpting helpers before final assembly (see below).
7. Builds the full `ReportContext` with every field: premise, factual status, equity focus, graph, central case, alternatives, `assumptions` filtered to only those `required_for_edge_ids` an active (non-rejected) edge, accepted/contradicting claims, `graph.estimates` (unfiltered — all estimates pass through regardless of whether their edge survived), findings, decisions, gaps, failures, and sources filtered to only those referenced by the surviving claims.
8. **Budget check**: `approximate_tokens(context) = len(context.model_dump_json()) // 4` (a crude chars/4 heuristic, not a real tokenizer) is compared against `token_budget`. If it fits, return as-is.
9. If over budget, it drops all *non-load-bearing* accepted claims (keeping only ones in the `load_bearing` set from step 4 — contradicting claims are never dropped by this pass), recomputes which sources are still referenced, and re-excerpts sources to that smaller set.
10. If it's *still* over budget after that, raises `ContextBudgetError` (a `ValueError` subclass) rather than truncating further or silently dropping load-bearing evidence — this is a deliberate fail-closed: the code comments explain that load-bearing claims are never truncated because they're what the writer actually reasons over.

**Excerpting** (`_excerpt`, `_excerpt_claim`): truncate `SourceRecord.extracted_text` to `SOURCE_EXCERPT_CHARS = 600` chars and `EvidenceClaim.exact_passage` to `CLAIM_PASSAGE_EXCERPT_CHARS = 400` chars, via `model_copy(update=...)` — non-destructive to the originals, only the copies embedded in the context are shortened. The comments justify both numbers concretely: an untrimmed source body (up to 80,000 chars from `PageFetcher`) alone could exhaust the default token budget, and even a claim's `exact_passage` — already the receipt of a completed verification, not raw material — became the dominant term once sources were excerpted. The full, untruncated text remains available elsewhere (in the persisted "sources"/"accepted_claims" artifacts), so this trimming only affects what's handed to the report-writing LLM call, not the durable audit record.

**`approximate_tokens(context)`** is exposed standalone and is the same heuristic used internally — callers elsewhere might use it to pre-check a budget before calling `compile_context`.

Input/output shapes: takes a `CandidateSeed`, `CausalGraph`, `CaseSelection`, and lists of `EvidenceClaim`/`SourceRecord`/`ChallengeFinding`/`AdjudicationDecision`/plain strings (`gaps`, `failures`), plus an integer `token_budget`; returns one `ReportContext` (or raises). Every field of `ReportContext` is populated by this function — there's no other code path that builds one, based on what's visible here. Feeds directly into `report.write_report(run_id, context, model, min_words, max_words)`, which serializes `context.model_dump_json()` verbatim as the LLM's `<INPUT_DATA>`.
