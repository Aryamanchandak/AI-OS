# `report/test_report.py`

One test, `test_context_and_invalid_citation_fail_closed`, exercising the seam between `report_context.compile_context` and `report.validate_report` (not `write_report`/`export_markdown` — no `ModelClient` is invoked; the `NewsletterReport` here is hand-constructed, not model-generated).

Builds a full but minimal `ReportContext` the same way `report_context/test_report_context.py` does (via the shared `graph` fixture, a `CandidateSeed`, one verified supporting `EvidenceClaim`/`SourceRecord`, and a `CaseSelection` around a hand-built central `Case`). Then constructs a `NewsletterReport` by hand with a valid-length `article_markdown` (`"careful analysis " * 55` plus a trailing `"[S9]"` — about 110 words, so it clears an 8-word substantiveness floor easily but is well below any realistic 800-1200 word production bound) and `source_ids_used=["S9"]`, where `S9` is **not** a real source in the context (the only real source is `S1`). Calls `validate_report(report, context, 50, 200)` (a loose 50-200 word bound, chosen just to let this particular article length pass so the test isolates the citation check) and asserts the returned error list contains an "unknown source" message.

This confirms the citation-integrity guardrail actually fires: a report citing a source ID that doesn't exist in the compiled context is not silently accepted. It does not check the specific wording of the error, doesn't verify that *other* checks (word count, assumption fidelity, prohibited language) stay silent when they should, and doesn't exercise the `source_ids_used`-specific branch separately from the inline-marker branch (both `[S9]` in the markdown and `S9` in `source_ids_used` would each independently trigger a failure here, so this test can't distinguish which check actually fired without reading the message).
